This release ships the liangshen row enabled by default and fills in its dispatcher identity and child-model selection, gives the task board native one-shot schedules with capped recurring runs and tightens its acceptance gate, and adds an install-all-missing bulk action to the Workshop. The usage Token Bank is now minted from an explicit route whitelist, the plugin manager reads the running DSH from its own manifest, and a dead SSH link retires its port-forward tunnel instead of taking the host down. The host floor is unchanged from `0.4.5` at `>=0.2.0-rc.2`, and no manual migration is needed. The four satellite repositories (skin center, pet, community plugin index, preset center) already published `0.4.6`; this repository tags afterwards and the aggregate consumes them by semver.

> **Important change (the host floor is unchanged at `>=0.2.0-rc.2`)**: this release does **not** move the `dsh.engines.dsh` floor the family packages declare, which has been `>=0.2.0-rc.2` since `0.4.5`, with the matching host peer kept in step, so no host preparation is needed for this update. `dsh-web-settings` retires the `0.1.7`-era orphaned-section repair (`legacy-import.ts` and its spec are gone): a deployment still relying on that automatic repair over settings documents left behind around `0.1.7` should check those documents itself, and every other scenario is unaffected; the settings-document readers themselves stay. Otherwise no persisted identifier, wire-protocol field or profile format was renamed, and the task board's new scheduling and acceptance fields fall back to the previous behaviour when absent.
